# Аудит адаптивности сайта RGballet

Анализ по коду (без проверки в браузере). Дата: 31 октября 2026.

Макеты в ТЗ: **1920 / 1440 / 1200 / 768 / 360**. В CSS **1440 нет**; вместо этого много локальных порогов.

## Карта брейкпоинтов

Общие (Media Queries Level 4, непрерывные):

| Порог | Где |
|---|---|
| `width >= 1920` / `width < 1920` | поля секций, футер |
| `width < 1200` | шапка, герой, часть секций |
| `768px <= width < 1200px` | планшет большинства блоков |
| `width < 768px` | мобильная вёрстка |

Локальные (не из ТЗ):

- **1921** — `Hero` (`min-width: 1921px`, старый синтаксис)
- **1620, 1030, 901** — `Pricing`
- **1236, 1000** — `Footer`
- **1061** — `Teachers` (+ `@container 1000–1730`)
- **960, 520** — `CookieBanner`
- **459** — `Program` (мобильный вид **не** на 768)
- **365** — `Hero`
- **767** — `<picture>` в `Teachers` (`max-width: 767px`)

JS совпадает с шапкой: `matchMedia('(width < 1200px)')` в `Header.astro` и `ScrollToTop.astro`.

## Системные разрывы

1. **ТЗ vs код.** 1440 не используется. Мобильное меню с **1200**, а не с 768. У `Program` мобильный карточный вид только **&lt; 459px**.
2. **Дыра 1920–1921.** У героя `min-width: 1921px`. На ширине между 1920px и 1921px не сработает ни «десктоп 1920», ни «ультраширокий» фон.
3. **Дыра 767–768 у фото педагогов.** CSS: `width < 768px`. Картинка: `max-width: 767px`. На дробной ширине ~767.5px стили уже мобильные, а `srcset` ещё десктопный.
4. **Пересечение у футера.** На **1200–1235px** одновременно:
   - `1200px <= width < 1920px` (ряд, `column-gap: 30px`);
   - `768px <= width < 1236px` (wrap, `gap: 75px`, другая геометрия).
5. **Жёсткие ширины/высоты** (`320px`, `600px`, `height: 787px`, `white-space: nowrap`) без `min-width: 0` / гибкой высоты — основной риск обрезания и горизонтального скролла.
6. Глобального `overflow-x: hidden` нет (это правильно). Горизонтальный скролл, если появится, будет виден.

## Проблемные места

### Критично (скорее ломается)

1. **`Pricing.astro`, 768–1030px**  
   Контент с `margin-right: 425px`, сетка/скидка/кнопка — `width: calc(100% + 425px)`. Блок намеренно вылезает вправо под фон танцовщицы, у секции нет `overflow`. Вероятны **горизонтальный скролл страницы** и обрезание карточек.

2. **`Pricing.astro`, &lt; 768px**  
   Секция с **фиксированной** `height: 787px` (не `min-height`). Стопка: заголовок + 4 карточки + скидка + кнопка почти заполняет 787px. Длинный текст скидки или крупный шрифт вылезут из секции.

3. **`Hero.astro`, 768–1199px**  
   У `h1` остаётся `white-space: nowrap` (снимается только `&lt; 768`). На узком планшете заголовок «Там, где линия тела становится музыкой» может выйти за край. Фон **1478×789** при `overflow: hidden` у секции — страница не уедет, но кадрирование жёсткое; с `&lt; 768` ещё `left: calc(50% - 40px)`.

4. **`Program.astro`, 459–767px**  
   Мобильная колонка и смена заголовка только при `&lt; 459`. На 360 макет есть, на **~500–767** карточки остаются **ряд: фото 142–185px + текст** в узкой колонке. Текст и отступы будут тесными.

5. **`FormModal.astro` / `YandexFormModal.astro`, около 768px**  
   Десктоп: модалка **600px**, поля **абсолютно** на 496px. Мобильный сброс только `&lt; 768`. На **768–820** ещё десктопная абсолютная сетка; при `max-width: calc(100vw - 40px)` поля могут не влезть. Мобильная модалка **320px** на экране 360–400px не растягивается (пустые поля по бокам).

### Высокий риск

6. **`Header.astro`, сразу выше 1200px**  
   Десктоп: 6 пунктов `nowrap` + лого + 3 иконки + `margin-left: auto` у соцсетей. Запас на 1200px небольшой. Между навигацией и иконками зазор может сжаться до нуля (типичная проблема плотного ряда). Пустой `@media (width < 768px)` ничего не делает.

7. **`About.astro`, 768–1199px**  
   Сетка фич остаётся **4 колонки** при ширине колонки ~160–200px и иконке 80px. Подписи «Индивидуальный пошив…» будут рваться на много строк или вылезать.  
   Превью видео: картинка **775×513**, `max-width: none`, клип через `overflow: hidden`. Подпись «Смотреть видео…» — `width: max-content`, на узком кадре может выйти за круг.

8. **`Opportunities.astro`**  
   Карточка **фиксированной высоты 217px**. Масштаб текста через `cqi` только при `1200px <= width <= 1920px`. На **768–1199** (2 колонки) длинные фразы («основной состав RG-ballet…», «зарубежом») могут обрезаться.  
   На мобиле высота **76px** + `line-height` до 30px — максимум 2 строки, иначе обрезка. Кнопка «Смотреть все» есть только `&lt; 768`.

9. **`Footer.astro`**  
   - **1200–1235:** конфликт двух запросов (см. выше).  
   - **1000–1235:** два столбца + `gap: 75px` + вертикальный разделитель 368px — отзывы и адрес будут очень узкими.  
   - `.contact-address-main { white-space: nowrap }` — длинный адрес на узкой колонке.  
   - Мобиле: `.footer-panel { width: 320px }`, на 361–767 панель не растёт.  
   - Юридическая ссылка длинная, без `overflow-wrap` в футере (на policy-страницах wrap есть).

10. **Галереи, 768–1199 и навигация**  
    `AtmosphereGallery`: с 6 колонок на 3, стрелки `position: absolute; right: 0` рядом со счётчиком и точками — на ~768px стрелки наезжают на точки.  
    `StudentsGallery`: на планшете 4-я колонка скрыта; заголовок `white-space: nowrap`. На 1200+ мозаика с `20vw` и 4 колонками — на 1200–1400 колонки узкие, высота считается от `20vw`.

### Средний риск

11. **`Teachers.astro`**  
    Два независимых переключателя: viewport `<= 1061` (1 колонка) и container `1000–1730` (2 колонки + первая карточка на всю ширину). Поведение на 1062–1199 зависит от ширины контейнера, не от ТЗ. Заголовок на мобиле `nowrap`. Карточка с колонкой фото 210px на промежуточных ширинах, пока не сработает `&lt; 768`.

12. **`Banner.astro`, &lt; 768**  
    `line-height: 60px` при `font-size` от 22px. Длинные заголовки приглашения/набора — либо огромные дыры между строками, либо визуальный разъезд блока.

13. **`GradientButton.astro`**  
    Всегда `white-space: nowrap`; на мобиле `width: 320px`. Длинный лейбл («Записаться на пробное занятие») на 320px с паддингами 36px может не влезть.

14. **`CookieBanner.astro`**  
    Ряд кнопок `min-width: 160 + 210` до 960px. На 960–1100 вместе с текстом ряд плотный; ниже 960 колонка — ок.

15. **Фиксированные `min-height` секций** (`Teachers` 1474, `Atmosphere` 856, `About` 810, `Opportunities` 542) на мобиле дают пустоту, а не скролл, но при росте контента не спасают, если рядом стоит ещё и фиксированная `height` у заголовка (`h2 { height: 100px / 180px }`).

### Ниже риска, но стоит знать

- `page-wrapper` ограничен 1920px; герой на &gt;1920 обрабатывается отдельно и другим синтаксисом.
- `ScrollToTop` только при `width < 1200`.
- Policy/consent перестраиваются только на 768.
- Форма в футере закомментирована — правила `:has(> .question-form)` сейчас почти мёртвые, но конфликт 1200/1236 остаётся.
