# Архитектура RG Ballet

## Технологический стек

| Часть | Выбор |
| --- | --- |
| Framework | Astro |
| Frontend | HTML, CSS, Vanilla JavaScript |
| UI-фреймворки | Не используются |
| React | Не используется по умолчанию; может быть добавлен позже отдельными компонентами после согласования |
| CSS | Обычный CSS без Tailwind |
| Адаптив | Собственная адаптивная вёрстка по макетам 1920 и 360 px |
| Макеты | Figma |
| Изображения сайта | `public/images` |
| Шрифты | `public/fonts` |
| Статические файлы | `public` |
| Исходные материалы | `.initial_data`, исключена из Git |
| Система контроля версий | Git и GitHub |
| Node.js среды разработки | 24.16.0 |
| npm среды разработки | 11.13.0 |
| npm registry | `https://npm-mirror.gitverse.ru` |

Версии Node.js и npm описывают текущую среду разработки. Требование проекта в `package.json`: Node.js `>=22.12.0`.

## Структура проекта

- `src/components` — компоненты секций и интерфейса.
- `src/layouts` — общие макеты страниц.
- `src/pages` — страницы Astro.
- `src/styles` — глобальные стили, шрифты и дизайн-токены.
- `src/config` — централизованные настройки проекта.
- `public/images` — изображения и SVG, доступные по пути `/images/...`.
- `public/fonts` — локальные веб-шрифты.
- `.initial_data` — макеты и исходные рабочие материалы, не публикуемые и не добавляемые в Git.
- `dist` — результат `npm run build`, готовый к публикации.

## Хостинг и деплой

Основной вариант — российский виртуальный веб-хостинг. Рассматриваются Timeweb и SpaceWeb, окончательный поставщик пока не выбран. Vercel не является целевой production-платформой.

Домен `rgballet.ru` зарегистрирован через REG.RU. В дальнейшем планируется переоформить домен и связанную инфраструктуру на ИП.

Планируемая схема деплоя:

1. Локальная разработка.
2. Репозиторий GitHub.
3. Сборка Astro командой `npm run build`.
4. Публикация содержимого `dist` на российском хостинге.

Для тестовой версии настроен автоматический деплой через GitHub Actions на GitHub Pages по адресу `https://dmitrybanin.github.io/RGballet/`. Это не меняет выбранную production-схему с российским хостингом.

## Формы и данные клиентов

Первая версия формы содержит только два поля:

- имя;
- телефон.

Интерфейс формы должен соответствовать макету Figma. Сторонние формы нельзя встраивать, если iframe или готовый интерфейс нарушает дизайн.

Планируемый поток заявки:

1. Собственная форма на сайте.
2. Российский сервис или серверная обработка.
3. Уведомление о заявке на email.
4. По возможности уведомление в мессенджер.
5. Передача заявки в выбранную CRM.

Минимальные статусы заявки: «Входящие» → «В работе» → «Отработано».

Яндекс Формы рассматривались как простой вариант обработки, но не должны определять внешний вид формы. Выбор между собственной админ-панелью, собственной CRM и внешней CRM пока не принят.

В будущем возможна онлайн-запись с выбором занятия или группы. В качестве одного из кандидатов ранее рассматривался Rubitime.

## Российская инфраструктура

Данные клиентов должны храниться и обрабатываться с учётом требований РФ. Предпочтение отдаётся российскому хостингу и российским сервисам.

Для production необходимы:

- SSL-сертификат;
- резервные копии;
- Яндекс Метрика после отдельного этапа настройки.

Корпоративную почту планируется перенести с `rg-ballet@mail.ru` на адрес домена, например `info@rgballet.ru`.
