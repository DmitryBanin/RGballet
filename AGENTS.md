# Правила работы

* Общайся только на русском.
* В обычных ответах пиши кратко.
* Код предоставляй полностью, когда изменяется целый файл.
* Не сокращай важные технические объяснения.
* Не пиши код, сперва алгоритм действий.
* Если есть упущение в действиях задай вопрос.
* Пиши действия которые мне нужно сделать поступательно.
* Перед изменением файла сначала составь план.
* Не меняй архитектуру проекта без необходимости.
* Не создавай новые зависимости без согласования.
* Используй существующий стиль кода.
* После завершения перечисли изменённые файлы.
* Перед началом работы ознакомься с:

  * README.md
  * docs/TZ.md
* Если в требованиях есть противоречия, сначала укажи на них
* Новые нерешённые вопросы записывай в `docs/QUESTIONS.md`.
* Принятые технические решения записывай в `docs/DECISIONS.md`.

## Технологический стек

* Framework: Astro.
* Frontend: HTML, CSS, Vanilla JavaScript.
* CSS-фреймворки и UI-фреймворки не использовать.
* React по умолчанию не использовать; добавление возможно позже только после отдельного согласования.
* Package manager: npm.
* Рабочая версия Node.js: 24.16.0.
* Рабочая версия npm: 11.13.0.
* npm registry: `https://npm-mirror.gitverse.ru`.
* Источник дизайна: Figma.
* Основные макеты: desktop 1920 px и mobile 360 px.
* Изображения сайта хранить в `public/images`.
* Остальные статические файлы хранить в `public`.

## Хостинг и деплой

* Production должен размещаться на российском хостинге.
* Основные кандидаты: Timeweb и SpaceWeb; окончательный вариант пока не выбран.
* Домен: `rgballet.ru`, регистратор — REG.RU.
* Не считать Vercel целевой production-платформой.
* Публиковать содержимое производственной сборки `dist`.
* GitHub и GitHub Actions для автоматического деплоя пока являются планируемыми решениями.

## Формы и CRM

* Форма должна визуально соответствовать Figma.
* Не встраивать стороннюю форму, если она нарушает дизайн.
* Поля первой версии формы: имя и телефон.
* Данные клиентов должны обрабатываться и храниться в инфраструктуре, соответствующей требованиям РФ.
* Новая заявка должна отправлять уведомление на email; уведомление в мессенджер желательно.
* Не реализовывать админ-панель или CRM до выбора варианта: собственная админ-панель, собственная CRM или внешняя CRM.
* Архитектура должна допускать последующую интеграцию сервиса онлайн-записи.

## Инфраструктура

* SSL обязателен.
* Резервные копии обязательны.
* Яндекс Метрика запланирована.
