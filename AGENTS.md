# RGballet — правила для Codex

## Порядок работы
- Общайся на русском, обычно кратко; важные технические пояснения не сокращай.
- Сначала изучи только файлы, относящиеся к задаче. Не перечитывай всю документацию и не сканируй рекурсивно `node_modules/`, `dist/`, `.astro/`, `.initial_data/`.
- До любых правок: объясни причину, перечисли затрагиваемые файлы, предложи краткий план и **дождись моего явного согласия**. Запрос на исправление сам по себе не считается разрешением на изменение файлов.
- Если для решения не хватает существенных данных или требования противоречат друг другу — сначала уточни. Действия для меня описывай пошагово.
- Не проверяй опубликованный сайт в браузере (включая скриншоты, измерения и взаимодействия) без отдельного объяснения цели и моего явного согласия.
- Сохраняй архитектуру и стиль проекта; новые зависимости, фреймворки и крупные изменения — только после согласования.
- Если меняется целый файл и я прошу код, предоставь его полностью. По окончании перечисли изменённые файлы и результат проверок; не утверждай, что проверка прошла, если её не выполнял.

## Комментарии в коде
- Пиши **краткие комментарии на русском** к неочевидным условиям, причинам решений, ограничениям, обходным решениям, интеграциям и обработке ошибок.
- Объясняй **зачем и почему**, а не пересказывай очевидные операции. Не комментируй каждую строку и не добавляй декоративные заголовки.
- При изменении логики обновляй или удаляй устаревшие комментарии. Для публичных API и сложных функций при необходимости используй JSDoc.

## Проект и документы
- Стек: Astro, HTML, CSS, Vanilla JS; без React, CSS/UI-фреймворков и CMS до отдельного согласования.
- Макеты: Figma (1920 и 360 px). Ресурсы: `public/images/`, `public/fonts/`, прочие статические файлы — `public/`.
- Документы открывай по необходимости: `README.md` (команды и деплой), `docs/TZ.md` (требования), `docs/ARCHITECTURE.md` (структура), `docs/QUESTIONS.md` (нерешённые вопросы). Новые открытые вопросы записывай в `docs/QUESTIONS.md` только после согласования правок.
- Основные точки входа: `src/layouts/BaseLayout.astro` (общий layout/SEO), `src/components/CookieBanner.astro` (согласие), `src/components/YandexMetrika.astro` (аналитика), `src/components/YandexFormModal.astro` (запись), `src/components/VideoModal.astro` (Kinescope), `src/config/contacts.js` (контакты и ссылки).

## npm и публикация
- Локальная среда: Node.js 24.16.0, npm 11.13.0; в GitHub Actions — Node.js 22. Используй совместимые с `package.json` версии.
- Локально допускается зеркало GitVerse, **но в `package-lock.json` поле `resolved` должно ссылаться на `https://registry.npmjs.org/`, не на `npm-mirror.gitverse.ru`**. После установки/обновления пакетов проверь lock-файл, не меняй версии или `integrity` без необходимости.
- В CI устанавливай зависимости воспроизводимо через `npm ci`. Не привязывай GitHub Actions к GitVerse; не меняй workflow и зависимости без согласования.
- Репозиторий: GitHub; деплой `dist/` на Timeweb через `.github/workflows/deploy-timeweb.yml`. Домен `https://rgballet.ru/` (REG.RU); HTTPS обязателен. Не снимай парольную защиту без разрешения.

## SEO, cookies и формы
- До согласованного публичного запуска сохраняй запрет индексации; не меняй `robots`, `canonical`, sitemap и SEO-флаги без явного разрешения. При запуске проверяй фактический HTML после сборки.
- Яндекс Метрику запускай **только после согласия на аналитические cookies**; при отказе не загружай аналитический скрипт. Не отправляй в аналитику ФИО, телефоны и email; учитывай Вебвизор.
- Яндекс Формы используются для заявок; береги согласие на ПД и не меняй способ обработки/передачи данных без согласования. Требования по ПД и РКН сверяй с актуальными документами проекта.
- Laravel, Filament и MySQL — возможная **будущая** админка/CRM, а не текущий стек сайта.
